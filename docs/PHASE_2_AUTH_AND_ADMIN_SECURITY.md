# 阶段 2：站长认证与管理端安全

## 1. 阶段目标

保护个人博客管理能力，确保只有站长或明确授权的管理员可以发布、修改和删除内容，同时让公开访客无需登录即可阅读已发布内容。

## 2. 认证策略

本阶段不把"开放注册"视为首版必需功能。根据阶段 0
审计结果选择最简单且安全的方案：

-   优先考虑单一站长管理员账户或受控管理员创建流程。
-   若保留现有注册 API，默认不开放公开注册，除非产品所有者明确要求。
-   若采用 JWT，统一 Token 的签发、验证、过期处理和密钥管理。
-   密码使用安全的自适应哈希算法存储，绝不保存明文密码。
-   管理接口必须由后端执行权限校验；不能只依赖前端隐藏按钮或路由。

## 3. 权限边界

-   公开访客：仅可查看已发布且允许公开的文章、分类和标签。
-   站长管理员：可以登录后台并管理文章、分类、标签和必要的站点设置。
-   草稿、未发布文章和管理接口：不得被匿名访问。
-   删除、发布、修改等操作：后端必须再次验证权限。
-   登录、密码错误、Token
    过期、无权限等情况应返回一致且不泄漏敏感信息的错误。

首版暂不设计复杂的普通用户角色、社交权限或多租户权限。若后续需要开放多用户投稿，再单独设计角色和内容所有权模型。

## 4. 工作内容

1.  审计 Spring Security 过滤链、认证入口、授权规则和密码编码器。
2.  确定站长账户初始化、密码重置和密钥轮换方式。
3.  统一登录状态与当前管理员信息接口。
4.  验证 Token 缺失、无效、过期和签名错误的行为。
5.  验证公开 GET 接口与管理写接口的权限边界。
6.  加入登录尝试限制或合理的防暴力破解措施（结合部署条件）。
7.  确保日志不记录密码、完整 Token 或密钥。
8.  为权限边界添加自动化测试。

## 5. 前端协作要求

前端使用 Vue Router 路由守卫和 Pinia
管理登录状态，但它们只负责导航和用户体验。真正的授权必须由后端执行。Axios
统一处理 401、403，并避免因错误重试导致循环跳转。

Token 存储方式需结合威胁模型决定。如果使用浏览器存储，应认识到 XSS
风险并配套防护；若采用 HttpOnly Cookie，则必须同时设计 CSRF
防护和跨站策略。不能在没有安全评估的情况下把 Token 存储方案写死。

## 6. 验收标准

-   [ ] 匿名访客可查看公开内容。
-   [ ] 匿名访客不能访问后台管理写接口。
-   [ ] 站长登录成功，错误密码无法登录。
-   [ ] 无效或过期 Token 会被拒绝。
-   [ ] 前端绕过路由守卫也无法绕过后端授权。
-   [ ] 草稿和未发布内容不会泄露。
-   [ ] 管理操作的权限测试通过。
-   [ ] 日志、配置和错误消息不泄露凭证。

## 7. 交付物

-   已确认的认证和权限设计。
-   管理端登录与当前管理员接口。
-   权限测试清单及测试结果。
-   管理员初始化与凭证维护说明。

## 8. 阶段完成定义

公开浏览和站长管理权限边界清楚且经过测试，可以安全地建设文章管理和前端页面。
