# 阶段 1：后端基础能力与数据模型

## 1. 阶段目标

基于阶段 0
的审计结果，修复阻断性基础问题，确保后端可以稳定构建、启动并访问数据库，为个人博客内容管理和公开展示提供可靠基础。

## 2. 产品原则

系统首先是个人学习笔记与兴趣分享站点。数据模型和接口优先满足站长维护文章、分类、标签及站点配置的需求；不要仅为未来可能存在的其他用户，提前引入复杂租户、组织、社交关系或多角色体系。

## 3. 技术约束

沿用经审计确认的后端栈：Spring Boot 3.4.0、Java 21、MyBatis-Plus
3.5.9、MySQL 8.0、Spring
Security/JWT、Redis（仅在实际需要时使用）、Maven。遵守 `CLAUDE.md` 的
MVC 分层和统一响应约定。若现有项目版本不同，先记录差异再决定是否调整。

## 4. 工作内容

-   整理配置：本地、测试和生产配置分离；敏感值从环境变量或部署密钥注入。
-   建立统一异常处理、参数校验、日志规范和健康检查。
-   核对 `Result<T>` 的成功与失败结构，避免各 Controller 自行包装。
-   核对数据库表、实体类字段、主键策略、时间字段、逻辑删除字段及索引。
-   为核心表提供可重复执行或有明确版本管理的初始化/迁移方案。
-   评估 `sys_user`
    是否仅承担站长后台登录；如保留认证，保证密码安全存储和管理员权限验证。
-   核查分页参数边界，限制最大页大小，统一列表响应结构。
-   添加必要的单元测试和基础集成测试。
-   记录 Redis 的必需性；不使用的组件不要成为本地启动的额外障碍。

## 5. 推荐数据领域

以审计后现有 Schema 为准，核心领域通常包括：

-   文章：标题、摘要、Markdown 正文、可选渲染
    HTML、封面、分类、标签、状态、发布时间、创建和更新时间。
-   分类：名称、slug、描述、排序和启用状态。
-   标签：名称、slug，以及文章关联关系。
-   站点配置（按需）：站点名称、简介、头像/标识、导航链接等。
-   管理员账户（若后台需要登录）。

不要在未确认需求时直接添加评论、关注、私信或其他社区数据表。

## 6. 验收标准

-   [ ] Maven 构建成功，构建失败原因已解决或明确登记。
-   [ ] 应用能按文档启动，配置不依赖开发者个人绝对路径。
-   [ ] 数据库连接和核心 CRUD 可验证。
-   [ ] 参数校验、统一异常和响应格式行为一致。
-   [ ] 敏感配置不硬编码、不提交到版本库。
-   [ ] 核心表结构与实体字段一致，逻辑删除行为经过测试。
-   [ ] 具备基础测试和健康检查方式。
-   [ ] 没有为未来社区功能无必要地扩张模型。

## 7. 交付物

-   稳定的后端基础工程。
-   数据库初始化或迁移脚本。
-   配置样例和启动说明。
-   基础测试结果及未解决问题清单。

## 8. 阶段完成定义

后端具备可重复构建、启动和连接数据库的能力，核心基础约定稳定，可以开始实现个人内容管理业务。
