# PHASE 6 施工单：真实联调与缺陷收口

> 交付对象：后端开发（WorkBuddy）+ PM（扣子）联合执行
> 基线：PHASE 5 完成后的 `main`
> 前置条件：`docker compose up -d` 三服务 healthy，前端可访问，能登录后台
> 目标：**前后端第一次在真实环境中跑通全链路**，把联调暴露的契约不一致逐条修掉

## 一、这一阶段的本质

前面所有验证都是封闭的：

- 后端测试用 Mockito 假对象 + MockMvc，没有真实 HTTP
- 前端用 mock 适配器，没有真实 axios 请求
- 两边从未在同一个进程环境里见过面

**PHASE 6 就是让这三样东西第一次同时出现：真实 HTTP + 真实 MySQL + 真实 JWT。**

所以这一阶段的产出不是新功能，而是「**一份把所有契约不一致都暴露出来并修掉的清单**」。

## 二、第一件事：关掉 mock

前端 `USE_MOCK` 默认是 `true`：

```js
// frontend/src/mock/index.js
export const USE_MOCK = (import.meta.env && import.meta.env.VITE_USE_MOCK) !== 'false'
```

联调前必须建 `frontend/.env.local`：

```
VITE_USE_MOCK=false
```

**验证方法**：浏览器 DevTools → Network，必须能看到真实的 `http://localhost/api/v1/...` 请求。看不到就说明还在 mock，此时任何「通过」都是假的。

> 容器部署时，`.env.local` 会被打进镜像。生产环境要确保 `VITE_USE_MOCK=false` 生效；如果 Dockerfile 构建时没有这个文件，默认还是 mock —— 这是最容易翻车的地方，必须在镜像里显式设成 `false`。

## 四、已知的契约坑（优先核查）

这些是前面阶段实际踩过的，联调时重点确认：

1. **`TagVO` 没有 `updatedAt`** —— 只有 `id/name/description/createdAt`。前端任何读 `updatedAt` 的地方都会显示 `-`
2. **`ArticleSaveRequest.title` 是 `@NotBlank`** —— 局部更新（如只改 status）不能只提交一个字段，必须整份提交
3. **`updateArticle` 内部 `getTitle().trim()`** —— `title` 为 null 会 NPE，不是返回 400
4. **`tagIds` 三态语义** —— 不传 = 不改，`[]` = 清空，数组 = 全量覆盖。前端必须严格区分「没拿到」和「空数组」
5. **`Result` 字段名是 `message` 不是 `msg`** —— 前端读错字段会导致错误提示为空
6. **分页响应是 `PageResult`** —— 字段 `list/total/pageNum/pageSize/pages`，不是 `records/total`
7. **草稿与下架的公开访问都是 404** —— 文案必须一致，否则等于泄露状态
8. **时间格式 `yyyy-MM-dd HH:mm:ss`** —— 由 JacksonConfig 统一，不要各处单独 `@JsonFormat`

## 五、缺陷处理规则

联调一定会暴露问题。按这个优先级处理：

| 级别 | 判定 | 处理 |
| --- | --- | --- |
| P0 | 数据丢失、越权、状态错误、白屏 | 立即修，修完重跑该用例 + 相邻回归 |
| P1 | 功能不可用但有报错提示 | 本轮修 |
| P2 | 展示错误、文案不一致 | 本轮修 |
| P3 | 体验优化 | 记入 `KNOWN_ISSUES.md`，不阻塞 |

**禁止**：为了让用例「通过」而改测试或改 mock。联调的意义就是暴露真实问题。

## 七、验收标准

1. 42 条用例**全部 PASS**，或 FAIL 项有明确说明且不属 P0/P1
2. `VITE_USE_MOCK=false` 下，Network 面板可见真实请求
3. 三条历史 P0 回归点全部确认：编辑正文不空、编辑已发布不变草稿、编辑不碰标签不丢标签
4. 访客端与后台在同一浏览器、同一环境内完成「登录 → 发文 → 访客看到 → 下架 → 访客 404」闭环
5. 后端日志无 500、无未捕获异常栈
