# 阶段 4：前端工程与页面建设

## 1. 阶段目标

使用已确定的前端技术栈建设完整的个人博客体验，并与真实后端 API
联调。前端不是独立的演示页面，不能把长期 mock 数据当作交付成果。

## 2. 确定技术栈

-   Vue 3
-   TypeScript
-   Vite
-   Element Plus
-   Vue Router
-   Pinia
-   Axios

生产部署使用 Docker 多阶段构建与 Nginx
提供静态文件。具体版本由项目初始化时选取并锁定，避免无必要地频繁升级。

## 4. 页面规划

### 公开页面

-   首页：个人简介、学习方向、最新文章或精选内容。
-   文章列表：分页、分类、标签和关键词筛选。
-   文章详情：阅读体验优先，清晰展示内容和元信息。
-   分类/标签页：浏览相关主题。
-   关于页面：个人介绍、站点目的和兴趣范围。
-   404、加载中、空状态与错误页。

### 管理页面

-   管理员登录。
-   后台布局与导航。
-   文章列表、创建、编辑、预览、草稿和发布。
-   分类与标签维护。
-   可选的站点信息维护。

不因 Element Plus
已安装就把公开博客做成纯后台管理风格。公开页面应重视阅读、内容层次、排版、响应式和个人特色；Element
Plus 主要用于后台表单、表格、弹窗和管理交互。

## 5. 工程约定

-   使用 `<script setup lang="ts">` 和 Composition API。
-   API 调用集中在 `src/api/`，Axios 实例统一配置。
-   类型放入 `src/types/`，避免无必要的 `any`。
-   环境变量只放非敏感配置；任何 `VITE_` 变量都可能暴露到浏览器。
-   本地开发可使用 Vite 代理；容器环境通过 Nginx 将 `/api/` 转发到后端。
-   路由守卫仅改善体验，后端仍须验证权限。
-   统一处理 401、403、404、429、5xx 和网络错误。
-   Markdown/HTML 渲染必须考虑 XSS 风险。
-   公开页面与管理页面共享 API
    类型和基础组件，但不把所有逻辑堆进单个组件。

## 6. 与后端联调顺序

1.  先验证健康检查和 API 基址。
2.  联调文章列表与详情，尽早确定内容字段和分页格式。
3.  联调管理员登录及当前用户信息。
4.  联调文章保存、发布、分类和标签管理。
5.  验证权限、异常、网络断开及无数据状态。
6.  如 AI 功能纳入首版，再接入 SSE。

后端接口与文档不一致时，记录差异并确认，不在前端擅自猜测字段。

## 7. 验收标准

-   [ ] 依赖可通过锁文件稳定安装。
-   [ ] TypeScript 检查和生产构建通过。
-   [ ] 首页、列表、详情和关于页面可访问。
-   [ ] 后台登录和内容管理使用真实 API。
-   [ ] 刷新嵌套路由不会出现错误的服务器 404。
-   [ ] 页面包含加载、空数据、失败和无权限状态。
-   [ ] 常见桌面与窄屏尺寸下布局可用。
-   [ ] 没有将密钥打包进前端。
-   [ ] 公开阅读体验与后台管理体验有合理区分。

## 8. 交付物

-   可构建的前端工程。
-   API 调用层、路由与状态管理。
-   公开博客页面和管理页面。
-   本地运行说明、环境变量示例及测试结果。

## 9. 阶段完成定义

用户可通过浏览器浏览个人公开内容，站长可通过受保护的管理页面维护内容，核心流程使用真实后端完成。
