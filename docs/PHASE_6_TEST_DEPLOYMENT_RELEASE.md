# 阶段 6：系统测试、容器部署与交付

## 1. 阶段目标

确保个人博客能在本地以容器方式完整运行，之后部署到目标服务器。交付不仅是"容器启动"，还包括真实业务验证、配置安全、数据持久化、备份恢复和资源观测。

## 2. 部署目标

-   第一目标：本地开发环境可完整运行和联调。
-   服务器基准：2 vCPU / 8 GiB RAM。
-   如果实测发现 CPU 压力持续过高且属于 CPU 瓶颈，再评估升级到 4 vCPU /
    8 GiB RAM。
-   若瓶颈是内存，单纯升级 CPU
    不会增加内存总量，应先优化服务、JVM、数据库和缓存配置，必要时再调整内存规格。

## 3. 建议容器架构

``` text
Browser
  |
  v
Nginx / Frontend container
  |-- /      -> Vue static files
  |-- /api/  -> Spring Boot backend
  |
  v
Backend container
  |-- MySQL 8.0 (internal network)
  |-- Redis (only if required)
  |-- External AI provider (if enabled)
```

具体服务应根据阶段 0
审计确认。若已有统一反向代理，应避免重复部署不必要的入口代理。

## 4. 容器要求

-   前端采用 Node.js 构建阶段与 Nginx 运行阶段的多阶段镜像。
-   使用 `npm ci` 和锁文件确保依赖安装可复现。
-   Nginx 配置 Vue Router SPA fallback，并将 `/api/` 转发到后端。
-   后端、MySQL、Redis 使用 Compose 内部网络及服务名通信。
-   不在容器中用 `localhost` 访问其他容器。
-   MySQL 数据使用持久化卷；明确备份和恢复流程。
-   数据库和 Redis 默认不直接暴露到公网。
-   密码、JWT 密钥和 AI Key 通过未提交的环境文件或部署密钥注入。
-   配置健康检查、合理重启策略和日志轮转。
-   固定并审查生产镜像版本，避免不受控地使用 `latest`。
-   生产环境尽可能使用非 root 用户，并定期更新基础镜像。

## 5. 本地全栈验证流程

1.  按文档准备本地环境变量。
2.  检查 Compose 配置。
3.  构建前端与后端镜像。
4.  启动全部依赖并检查健康状态。
5.  验证前端首页、静态资源与 API 反向代理。
6.  验证站长登录、文章创建、草稿保存、发布、列表和详情。
7.  验证匿名访客无法查看草稿或调用管理写接口。
8.  若 AI 纳入当前版本，验证 SSE 流式输出和错误场景。
9.  重启容器，确认数据库数据仍然存在。
10. 测试配置缺失、数据库不可用、后端错误等常见故障的诊断方式。
11. 从备份恢复数据库，验证恢复流程可执行。

常用命令示例（仅在相应文件已创建并核对服务名后使用）：

``` bash
docker compose config
docker compose build
docker compose up -d
docker compose ps
docker compose logs -f
```

停止服务时，不要随意删除数据库卷；任何破坏性操作前先备份并确认数据影响。

## 6. 服务器资源验收

在目标服务器上观察代表性使用负载下的：

-   主机与容器 CPU 利用率。
-   内存占用、容器 RSS、OOM 事件和 Java GC。
-   请求响应时间、错误率和并发情况。
-   MySQL 连接数、查询延迟及缓存配置。
-   Redis 内存（若启用）。
-   磁盘空间、Docker 日志增长和备份占用。
-   AI 功能（若启用）带来的额外连接和并发压力。

不要在没有数据的情况下设定虚假的精确资源阈值。先建立实际基线，再制定告警阈值。升级
CPU 的决策应由观测结果支持。

## 7. 安全与运维检查

-   [ ] 生产环境未暴露不必要的数据库和缓存端口。
-   [ ] 仓库和前端静态资源中没有真实凭证。
-   [ ] HTTPS 与域名配置方案已明确（公网部署时）。
-   [ ] 数据库备份定期执行且恢复流程经过演练。
-   [ ] 日志轮转生效，不会持续占满磁盘。
-   [ ] 有明确的升级、回滚和故障排查步骤。
-   [ ] 管理端仅授权访问，草稿和未发布内容不公开。
-   [ ] 应用依赖、镜像和系统更新策略明确。

## 8. 最终验收标准

### 工程

-   [ ] 前端依赖安装、类型检查和生产构建通过。
-   [ ] 后端构建和测试通过。
-   [ ] Docker 镜像可从源码重新构建。
-   [ ] Compose 能从已记录的步骤启动完整服务。

### 业务

-   [ ] 站长能安全登录并维护文章、分类和标签。
-   [ ] 访客可以浏览公开文章列表和详情。
-   [ ] 草稿、权限和错误处理符合预期。
-   [ ] 页面在常见桌面和窄屏尺寸下可用。

### 运维

-   [ ] 容器健康状态正常，服务间网络可用。
-   [ ] 数据持久化、备份和恢复经过验证。
-   [ ] 本地全栈容器部署成功后，才进入服务器部署。
-   [ ] 2 vCPU / 8 GiB
    实测数据已记录；若不满足目标，有瓶颈分析和后续决策。
-   [ ] 部署、日志查看、更新、回滚和恢复文档完整。

## 9. 交付物

-   `docker-compose.yml` 及经确认的生产配置。
-   前后端 Dockerfile、Nginx 配置和 `.env.example`。
-   `docs/DEPLOYMENT.md`：本地、服务器部署与排错步骤。
-   测试报告、资源观测记录、备份恢复记录。
-   已知问题与后续迭代清单。

## 10. 阶段完成定义

本地可从记录的步骤启动完整容器化系统，核心业务通过验证，数据可持久化并可恢复；服务器部署和资源决策有可复现的依据。
