# 阶段 3：个人博客核心业务

## 1. 阶段目标

实现网站的核心价值：持续记录个人学习过程、技术实践、读书笔记、项目复盘和兴趣爱好，并以清晰、易读的方式向访客展示。

## 2. 首版业务范围

必须优先完成：

-   文章创建、编辑、草稿保存、发布、下架或删除。
-   分类与标签管理。
-   公开文章分页列表、详情、分类/标签筛选和关键词搜索（如后端范围允许）。
-   Markdown 内容存储与安全渲染。
-   站点基础信息，如标题、简介和导航（按需求决定是否做成可配置项）。

首版不强制提供评论、点赞、收藏、关注、用户投稿、私信、通知中心等社区功能。

## 3. 内容模型与分类建议

内容应方便表达个人学习和兴趣，而不局限于技术教程。可考虑使用分类组织内容，例如：

-   技术学习：编程、框架、工具与实践。
-   学习记录：课程笔记、读书笔记、阶段总结。
-   项目实践：开发日志、问题排查、复盘。
-   兴趣分享：摄影、旅行、音乐、游戏或其他个人爱好。

这些只是建议的内容分类，不要求在代码中硬编码。分类应可由站长在后台管理。

标签用于跨分类描述主题；slug
应稳定且唯一。文章状态、发布时间和可见性规则必须明确，公开列表只返回允许公开的内容。

## 4. 后端工作内容

-   核对并实现文章 CRUD、逻辑删除及状态流转。
-   列表支持分页与约定的筛选条件。
-   详情接口返回前端所需字段，避免暴露内部或敏感字段。
-   分类支持树状结构时，明确根节点、排序和删除约束。
-   实现标签维护及文章-标签关联。
-   统一 Markdown 与 HTML 的职责，明确由后端转换还是前端渲染。
-   校验标题、摘要、正文、分类、标签及状态等字段。
-   对公开接口设置合理的查询边界与错误处理。

## 5. 前端工作内容

-   首页：表达站点主题、个人简介或近期学习方向，并展示最新内容。
-   文章列表：清晰展示标题、摘要、分类、标签、时间和分页。
-   文章详情：支持可读的排版、目录（可选）、代码块和移动端布局。
-   后台文章管理：列表、筛选、编辑、预览、草稿和发布。
-   分类与标签管理：表单校验、排序和关联提示。
-   提供加载、空结果、错误、未找到和无权限等状态。
-   Markdown 编辑器应支持预览；内容保存后需验证前后端渲染一致。

## 6. 内容安全与质量

-   不把未经清洗的 HTML 直接注入页面。
-   文章列表和详情必须正确过滤草稿、下架和逻辑删除内容。
-   防止重复提交、错误覆盖和误删除。
-   长文章、代码块、图片缺失和窄屏阅读均需测试。
-   文章内容应由站长管理；公开访客只拥有阅读能力。

## 7. 验收标准

-   [ ] 站长可以创建、编辑、保存草稿并发布文章。
-   [ ] 发布文章可以从公开列表进入详情页。
-   [ ] 草稿和下架内容对匿名访客不可见。
-   [ ] 分类、标签创建和关联行为正确。
-   [ ] 分页、筛选和详情字段与 API 契约一致。
-   [ ] Markdown、代码块、链接和图片显示符合预期。
-   [ ] 危险 HTML 与脚本注入经过测试。
-   [ ] 删除、失败保存和网络异常有明确反馈。
-   [ ] 内容模型没有强制引入多用户社区机制。

## 8. 交付物

-   可用的文章与分类标签 API。
-   博客公开页面及管理端核心页面（可随阶段 4 分批实现）。
-   业务验收用例和已知问题清单。

## 9. 阶段完成定义

站长能完整管理内容，访客能稳定浏览公开内容，网站已具备个人学习与兴趣分享的核心价值。
